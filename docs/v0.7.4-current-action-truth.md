# v0.7.4 — Current Action Truth

## Problem 1: false red owner action

The authoritative mission feed can contain text such as:

```text
None for current repository-local work. Future real-data/provider binding, risk mandate, paper start and every live phase require explicit human approval.
```

That statement describes **no current human gate** plus future safety boundaries. The runtime presentation layer already recognized this distinction, but some UI consumers still received the raw `mission.needsHuman` string and independently treated every non-empty string as an active action.

### Fix

- `runtime-snapshot-repair.ts` now classifies `None for current ...` / equivalent current-clear wording as a clear current gate.
- `runtime-snapshot-presentation.ts` keeps the original wording in `sourceSnapshot` and `presentation.humanGateFutureOnly`, but presents `mission.needsHuman = null` when the message is explicitly future-only.
- Manual invocation safety continues to use the repaired runtime before presentation; unknown or genuinely active gates remain fail-closed.

Result: the OS can show future paper/live/provider/broker/risk approvals as safety boundaries without showing a false red **Actie nodig** card today.

## Problem 2: compute telemetry is absent upstream

The web OS already understands the Runtime Snapshot v1 compute contract. It will populate the dashboard as soon as the authoritative VPS state feed publishes a compute object. The web layer intentionally does not infer or fabricate these values.

Expected payload shape:

```json
{
  "runtime": {
    "compute": {
      "runs_24h": 0,
      "max_runs_24h": 6,
      "prompt_tokens_24h": 0,
      "max_prompt_tokens_24h": 600000,
      "total_tokens_24h": 0,
      "max_total_tokens_24h": 700000,
      "open_reservations": 0,
      "voided_reservations": 0,
      "estimated_context_bytes": 0,
      "max_context_bytes": 80000
    }
  }
}
```

The corresponding authoritative sources are expected to remain VPS-side, e.g. the compute budget, reservation ledger, reconciled native usage, reservation void ledger and latest run manifest. Credentials, prompts and response bodies must never be published.

### Root-cause boundary

There is no VPS state-publisher implementation in this Next.js repository. `/api/os/snapshot` only reads the configured `HERMES_AUTONOMY_STATE_URL` and normalizes fields that are actually present. Therefore empty compute cards while `telemetry.stateFeed=true` mean the upstream state feed is connected but not publishing the compute object yet.

Do not add a web-side estimated fallback. The fix belongs in the authoritative VPS publisher / atomic admission layer.
