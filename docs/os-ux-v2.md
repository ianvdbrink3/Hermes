# Hermes OS UX v2

Approved scope: the entire OS, including Overview, Research, owner actions, Trading, Settings, System status, improvement tools and login. Shared calm visual language, readable typography, mobile navigation and keyboard access.

Each screen leads with what is happening, why it matters and the next useful action. Technical evidence remains available through disclosure. Trading separates the CIO decision, risk verdict and paper execution; confidence is not presented as a calibrated success probability. Missing, stale and insufficient evidence remain explicit.

Existing API authentication, runtime policies, trading safety and shadow observation rules remain authoritative. No new broker controls or automatic model invocations are introduced by presentation changes.

## Plain Dutch explanations — 2026-10-08

Daily screens use concise Dutch presentation derived conservatively from stored structured states and explicit assessment conclusions. The authenticated /analyses page retains original decision theses, invalidation conditions, latest agent reports, provenance, original dates, system explanations and capability descriptions. Frozen decision evidence stays separate from newer research. Unknown prose is never guessed into a positive assessment; precise unknown conditions point to the original text. Risk approval remains separate from execution. No trading decisions, source dates, journals, risk rules or access controls are changed. Brain Studio requests concise Dutch conversational output while preserving its existing policy gates.

Regression tests cover missing macro evidence, signed scores, unknown prose, quoted/conditional/prior forecasts, false AI matches, negation and exact invalidation conditions. Browser verification uses a local isolated read-only mock with all POST requests blocked.


### Concrete uitleg bij vastgelegde besluiten

De dagelijkse uitleg noemt Windows-licenties/apparaten en Xbox-games/diensten uitsluitend wanneer de vastgelegde bedrijfsanalyse die dalingen expliciet noemt. Koersrendementen verwijzen naar de periode vóór de analyse; het technische volatiliteitscijfer blijft bij de oorspronkelijke uitgebreide analyse.
